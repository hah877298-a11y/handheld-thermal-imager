- 日期：2026-10-05
- 硬件：正点原子精英板 STM32F103ZET6 + GY-MCU90640（PS 接 GND，I2C 直通模式）
- 固件：定点 Q8 双线性插值（HARDWARE/INTERP）+ 铁红 LUT（HARDWARE/PALETTE），KEY0 切换最近邻，-O2 优化

## 二、渲染性能与优化历程（论文"性能优化"章节素材）

| 阶段 | 渲染总耗时 | 手段 |
|---|---|---|
| 初版 | 119ms | 基准（FSMC 全 0x0F + -O1 + 朴素双线性） |
| ① | 116ms | FSMC 写时序收紧（ADDSET=0x0F→1、DATAST=0x0F→2；读时序未动）——仅微降，证明刷屏非主瓶颈 |
| ② | 52ms | 双线性算法重构：水平插值与输出行号无关，8 条输出行共用一次（乘法量↓2.7 倍）+ -O2 + 指针化热循环 |
| ③ 最终 | 47ms | 分段计时修正后实测：map 1ms + interp 30ms + fill 15ms（+色带文字 ~1ms） |

- 最终每像素成本：插值+查色 ~21 周期/像素操作；LCD_Color_Fill 刷屏 22 周期/像素（306ns，接近 FSMC 总线极限）
- ④ 撕裂防护（联调中发现并修复）：bit-bang 读帧 200ms 占帧周期 80%，偶发跨越子页边界 → 横向色条畸变。修复：读帧后重读状态寄存器做子页一致性校验（切换即拒帧）+ 启动垃圾帧自适应丢弃（含 0 值像素的陈旧帧，最多 3 帧）。修复后画面稳定，最终实测 r=43ms（map 1 + interp 28 + fill 13）
- 帧预算：250ms = 读帧 200ms + 渲染 47ms，余量 ~3ms
- **遗留优化项**（功能 3/4/6 需要余量时再做）：LUT 表移入 RAM（查色 512B 常量表目前走 Flash 随机访问，估计可省 5~8ms）；bit-bang I2C 提速至 400kHz（读帧 200ms→40ms，配合可回 8Hz）

## 三、过程中的关键问题

1. **r=119ms 超预算 3 倍**：分段计时定位——先误判为 FSMC 时序（实测 fill 仅 15ms），后确认主瓶颈是 -O1 下朴素双线性的每像素 155 周期 → 算法重构（水平插值跨行共用）+ -O2 + 指针化
2. **Keil GUI 与 CLI 构建冲突**：GUI 打开时 CLI UV4 -b 会挂起（工程文件锁）；GUI 内存中的旧工程设置（如优化等级）会在烧录时重建并覆盖磁盘修改——改 uvprojx 前必须关闭 Keil，烧录前需重新打开让其加载磁盘设置
3. **GBK 文件编辑陷阱**：Edit 工具写入含中文的 GBK 文件会导致注释乱码（整文件转 UTF-8+U+FFFD），改 main.c/interp.c 一律用 python `decode('gbk')/encode('gbk')` 脚本；printf 里的 `\r\n` 经 shell/python 转义层会变成真换行，用 `bytes([92])` 构造反斜杠
